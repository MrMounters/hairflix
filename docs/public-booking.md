# Public homepage and private app entry

The marketing homepage, its root assets, privacy page and booking entry are public even when SITE_ACCESS_ENABLED=true. The invitation gate remains on /login/, /app/, app assets and private APIs. The public footer's Log in link opens /welcome/?next=%2Flogin%2F, which returns authenticated visitors to workspace selection. No homepage redirect to the Good Chair invitation is needed.

All public booking CTAs use the existing repository's Hairflix Squire destination: https://getsquire.com/booking/brands/hairflix-barbershop. The enhancement opens this hosted booking flow in a modal iframe with a permanently available external-link fallback; without JavaScript the link opens directly. It does not create slots, take deposits, or claim bookings through the local prototype. Shop tabs never replace it with the old local calendar. Legacy /book.html now uses the same provider entry.

External verification limitation: the environment proxy denies Hairflix's live website and getsquire.com, so the exact embed SDK on the existing website and provider frame permissions were not verified. This is a local modal around the known Squire URL, not a claim to have copied the official website's embed SDK. If Squire restricts framing, visitors can use the direct booking link. Network domain additions were saved to the environment draft for review; they were not applied by that save.

Validation: 43 automated tests pass, including public versus private route boundaries. Chromium checks cover public homepage without a cookie, footer-only login through the invitation page, all booking links, panel open/close/Escape, restored focus, mobile panel size and the legacy booking entry. The external provider was mocked for browser wiring checks; no real appointments were made.
